## C. 우선 확장 기능 (사용자 선택: 인플레이션 · 생활비 · 부동산 매각)

### C-1. 물가상승률(인플레이션) 반영 ⭐ 최우선

**문제**: 분석 구간이 2030~2065년(36년)인데 모든 금액이 명목값(미래 시점 원화)으로 표시된다.
65세 128만원과 90세 47,195천원/년은 **실질 구매력**이 전혀 다르다.

**설계**:
- 전역 인플레이션 슬라이더 `0~5%` (기본 2.5%), `PensionContext`에 `inflationRate` 추가
- 두 가지 표시 모드 토글: **명목값** ↔ **실질값(현재가치)**
  - 실질 환산: `real = nominal / (1 + r)^(age - currentAge)`
  - 기준연도: 현재(2026, 53세)
- 적용 대상: 현금흐름 차트 Y축, KPI 카드, 사이드바 요약, 생활비 비교
- 주의: 국민연금은 실제로 **물가연동(소비자물가 반영 재평가)**되므로,
  명목 배열 자체에 일부 상승이 내재. 실질 모드에서 이중 반영되지 않도록
  "국민연금은 물가연동 가정"이라는 옵션 분리 권장.

**필요 데이터**: 없음 (가정 슬라이더). 단, 국민연금 명목 배열이 물가 반영인지 여부 확인 필요.

**파일**: `PensionContext.jsx`(상태), `CashFlowDashboard.jsx`(축·라인), `PensionSidebar.jsx`(요약), 신규 `utils/inflation.js`

---

### C-2. 생활비 목표 입력 → 부족/잉여 ⭐ 최우선

**문제**: 수입(연금+임대)만 보이고, **얼마가 필요한지**가 없어 "은퇴 준비 충분 여부" 판단 불가.

**설계**:
- 입력: 월 목표 생활비(만원), 선택적으로 **연령 구간별 차등**
  (활동기 55~70 / 안정기 71~80 / 의료기 81~90 — 의료비 증가 반영)
- 계산: `surplus(age) = 세후수입(age) - 생활비목표(age)`
- 시각화:
  - 현금흐름 차트에 **생활비 목표 라인**(점선) 오버레이 + 부족 구간 음영
  - KPI: "부족 시작 연령", "누적 부족액", "최저 잉여 연도"
  - 인플레이션(C-1)과 결합 시 생활비도 물가상승 적용
- 의료비는 별도 항목으로 분리 입력 가능(81세+ 가산)

**필요 데이터**: 사용자 입력(월 생활비, 의료비 예상). 외부 참고치(통계청 가계동향/노후 적정생활비)는 placeholder로 제공.

**파일**: `PensionContext.jsx`(생활비 상태), 신규 `screens` 또는 `IncomeInput.jsx` 확장, `CashFlowDashboard.jsx`(오버레이)

### C-3. 부동산 매각 시나리오 (양도소득세) ⭐ 최우선

**문제**: 26억 부동산은 현재 **건보료 재산점수 입력값**으로만 쓰임.
매각해 생활비/유동성 확보 시의 **양도세·건보료·소득 변화**가 미반영.

**설계**:
- 입력: 매각 연령, 취득가액, 양도가액(또는 시세), 보유기간, 1주택 여부, 거주기간
- 계산(양도소득세 추정):
  1. 양도차익 = 양도가 − 취득가 − 필요경비
  2. 1세대1주택 비과세(12억 한도) / 초과분 과세 / 장기보유특별공제(보유·거주 기간별 최대 80%)
  3. 양도소득 기본공제 250만 → 과세표준 → 양도세율(누진) + 지방세 10%
  4. 다주택 중과 여부(정책 변동 — 확인 필요)
- 매각 후 연쇄효과:
  - **건보료 재산점수 하락** → 보험료 감소 (기존 `localSubscriberPremium` 재활용)
  - **임대소득 소멸**(임대용 매각 시) → 종합소득·피부양자 자격 변화
  - 매각대금 → 금융자산 전환 시 **금융소득** 발생 가능(2,000만 종합과세 기준)
- 시각화: "매각 vs 보유" 비교 카드 (순현금, 건보료, 세부담)

**필요 데이터**: ⚠️ **취득가액, 취득일(보유기간), 거주기간, 주택 수, 임대/실거주 구분**.
양도세는 이 값들에 매우 민감하므로 사용자 확보 필수.

**파일**: 신규 `utils/capitalGainsTax.js`, 신규 화면 또는 `HealthInsurance.jsx` 시나리오 확장, `userData.js`(부동산 상세 필드)

## F. 관련 연금·세제 컨텍스트 (참고 — 구현 시 연도 기준 재확인)

> 아래 수치는 일반적으로 알려진 제도 기준이며, **앱에 넣기 전 반드시 해당 연도 공식 자료로 검증**해야 한다.

**사적연금(세제적격) 분리과세**
- 연금소득 **연 1,500만원 이하**: 저율 분리과세 3.3~5.5%(연령별: ~69세 5.5%, 70~79세 4.4%, 80세+ 3.3%)
- 초과: 전액에 대해 ① 종합과세 또는 ② 16.5% 분리과세 중 선택
- (현재 코드 1,200만 → 1,500만 갱신 필요: C1)

**국민연금 조기·연기**
- 조기노령연금: 1년당 6%(월 0.5%) 감액, 최대 5년 30% 감액
- 연기연금: 1년당 7.2%(월 0.6%) 가산, 최대 5년 36% 가산
- (현재 코드는 연기만 ×1.36 단순 반영)

**건강보험 피부양자 탈락 기준(일반)**
- 연 소득 2,000만원 초과 시 탈락 / 재산 과표 9억 초과 / 과표 5.4억~9억 + 소득 1,000만 초과
- 본 사용자: 임대 3,600만 + 부동산 26억 → **탈락 확정, 지역가입자 전환**

**양도소득세(1세대1주택 일반)**
- 12억 이하 비과세 / 초과분 과세, 장기보유특별공제(보유+거주 기간별 최대 80%)
- 기본공제 250만, 누진세율 6~45% + 지방세 10%
- 다주택 중과·일시적2주택 특례는 정책 변동 큼 → 확인 필수

**연금소득공제(국민연금 등 공적연금)**
- 350만 이하 전액 … 1,400만 초과 시 630만+초과분 10%, 한도 900만

## G. 단계별 구현 로드맵 (제안)

**0단계 — 정확성(반나절)**: C1(1,500만), C6(기준연도 라벨), 상수 `taxConstants.js` 분리
**1단계 — 인플레이션(C-1)**: Context 상태 + 차트/KPI 실질·명목 토글
**2단계 — 생활비(C-2)**: 생활비 입력 + 현금흐름 부족/잉여 오버레이 (1단계와 결합)
**3단계 — 부동산 매각(C-3)**: `capitalGainsTax.js` + 매각/보유 비교 + 건보료 연동
**4단계 — 영속화·상세근거**: localStorage, 세금 분해 카드
**5단계 — 배우자·IRP 인출전략**: 별도 프로필 탭

**공통 원칙**
- 단위 규칙 유지: 데이터 천원/년 → ÷10÷12 = 만원/월
- 모든 세금/건보 결과에 "추정 · ○○년 기준" 라벨
- 새 상수는 `taxConstants.js` 단일 출처
- 기존 유틸 재사용: `localSubscriberPremium`, `comprehensiveIncomeTax`, `pensionIncomeDeduction`

## H. 요약

- **즉시**: 사적연금 한도 1,200→1,500만 수정, 기준연도 라벨, 상수 분리
- **우선 3종**: 인플레이션(실질가치) → 생활비(부족/잉여) → 부동산 매각(양도세) 순서로 결합 구현
- **데이터 갭**: 6개 상품 현재 적립금, 부동산 취득정보(양도세), 배우자 정보가 가장 큰 공백
- **차순위**: 배우자 통합, IRP 인출전략, 국민연금 조기/연기 정밀화, 입력 영속화
